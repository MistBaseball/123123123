# 재현과 검증

## 웹 자동 검사

Node.js 24, `web` 폴더에서:

```sh
npm ci
npm test
npm run typecheck
npm run build
```

`npm test`는 Node의 TypeScript 타입 제거로 실제 엔진을 불러온다. 테스트 프레임워크나 브라우저를 별도 설치하지 않는다. `npm run build`에도 typecheck가 포함되어 있다.

현재 27개 검사는 다음을 포함한다.

- 투구 구속/도착, 존 경계, 구종 목표 고정, 중복 클릭 차단, 일시정지/리셋.
- 8가지 베이스 점유의 고의4구, 볼넷/삼진/2스트라이크 파울/번트.
- 안타·장타·홈런 진루, 세 번째 아웃과 득점.
- 주루 순서와 양 렌더러 방향, 늦은 1루 송구가 이미 2루에 도착한 타자를 아웃시키지 않음.
- 2루 포스 대상 선택, 비포스 점유 베이스 세이프, 베이스 사이 태그.
- 플라이 즉시 아웃/1루 무송구, 포구 실패 후 진루, 포구 이후 태그업.
- 실제 궤적과 구종 움직임 표시의 범위 일치.
- 30/60/144FPS 접전 판정, ±5ms와 동시 도착 세이프.
- 명시적 공수 교대, 끝내기·생략된 말 공격·무승부·종료 1회 기록.
- 중단 경기의 누적 기록 오염 방지, 훈련·회복·피로·컨디션·진로.
- 시드를 고정한 3이닝 5경기와 9이닝 1경기 전체 진행.
- 타격 피드백의 조준/타이밍/노스윙 구분.

새 규칙 버그는 작은 결정적 시나리오로 검사한다. 랜덤 경기를 무작정 더 돌려 검사한 것으로 대체하지 않는다. 테스트가 TypeScript private 메서드의 런타임 접근을 사용하는 부분은 검사 전용이며, UI가 내부 판정을 중복 구현하라는 뜻이 아니다.

## 최근 네 수정의 수동 확인

| 항목 | 확인 방법 | 기대 결과 |
|---|---|---|
| 주루 방향 | 탑뷰/포수 카메라에서 인플레이 관찰 | 홈→오른쪽 1루→2루→3루, 몸이 진행 방향을 봄 |
| 잘못된 1루 아웃 | 수동 송구로 늦게 1루에 던지는 상황 관찰 | 이미 안전하게 진루한 타자는 남음. 정확한 강제 시나리오는 자동 검사 사용 |
| 플라이 아웃 | 수비수가 떨어지기 전 잡는 타구 관찰 | 포구 즉시 FLY OUT, 1루 송구 없이 타자 아웃 |
| 구종 범위 | 불펜에서 1–4로 구종을 바꿔 조준 | 색 영역/방향/cm가 바뀜. 최종 목표와 제구 오차는 별개 |

## 화면과 조작 점검

1. `npm run dev` 후 localhost:5173을 열어 경기장과 메뉴가 보이는지 확인한다.
2. 불펜에서 네 구종을 클릭 투구한다. 비행 중 마우스를 옮겨도 목표가 고정되어야 한다.
3. 배팅 케이지에서 조준+클릭/Space로 타격하고 타이밍/오차 피드백을 확인한다.
4. 설정에서 자동 수비를 끄고 WASD와 인플레이 1–4 송구를 확인한다.
5. 도움말·설정·훈련 화면에서 경기가 일시정지되고 돌아오면 정상 재개하는지 확인한다.
6. 3아웃 후 공수 교대 버튼, 경기 종료, 새 경기 확인 대화상자를 확인한다.
7. 불펜으로 전환한 뒤 이름/훈련을 바꾸고 새로고침해 선수 기록이 남는지 확인한다. 진행 중 경기 복원은 기대하지 않는다.
8. 좁은 창과 1920×1080 창, 5개 카메라, 효과음을 확인한다.
9. WebGL 지원 브라우저에서 Three.js 화면, WebGL 비활성 환경에서 호환 그래픽 화면을 각각 확인한다. 라벨이 canvas를 지우지 않아야 한다.

수동 목록은 전달받는 개발 환경에서 확인할 체크리스트다. 이번 수행 여부는 `VALIDATION.md`만 참고한다.

## Unity 검사

패키지 `README_KO.md`의 설치/Inspector/16개 테스트가 기준이다. 실제 Unity에서 생성 메뉴와 검사 메뉴를 실행한 뒤 Play Mode를 확인한다.

독립 수치 검사는 Python 3 + NumPy 환경에서:

```sh
cd unity/PitchingMouseMVP
python Validation/verify_numeric.py
```

NumPy가 없다면 Python 환경에 준비해야 한다. 웹 실행에는 Python이나 NumPy가 필요하지 않다. 이 수치 검사는 C# 실행 결과나 Unity 빌드 성공을 대신하지 않는다.
