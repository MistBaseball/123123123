[프로젝트명]
투수 중심 3D 야구 선수 육성 게임

[개발 환경]
- Unity 기반 3D 게임
- PC 프로토타입 우선
- 추후 모바일 대응 가능하게 설계
- 개발자는 Unity 완전 초심자
- 코드는 C#
- 가능한 한 무료 에셋 / 오픈소스 / 기본 Unity 기능 사용
- 처음부터 거대한 완성작을 만들지 말고 MVP → 확장 방식으로 제작
- 모든 기능을 모듈화하여 나중에 교체 가능하게 설계
- 코드를 작성할 때 어느 GameObject에 어떤 Script를 붙이는지도 반드시 설명

==================================================
0. 가장 중요한 개발 원칙
==================================================

이 게임은 단순 야구 시뮬레이션이 아니다.

플레이어가 고등학교 3학년 야구선수 한 명이 되어
훈련하고 성장하고 실제 경기에 출전하고
스카우트 평가를 받아 프로선수가 되는
"야구 선수 인생 육성 게임"이다.

그중에서도 가장 중요한 플레이는 투수다.

경기에서 플레이어는 직접 구종과 코스를 선택하여 공을 던진다.

게임 핵심 재미:

1. 직접 투구
2. 구종별 무브먼트
3. 성장
4. 능력치 차이를 실제 조작감으로 체감
5. 타자와의 심리전
6. 피로와 스태미나 관리
7. 실제 야구 같은 수비 움직임
8. 고교 → 프로 → 장기 커리어
9. 희귀 구종 / 히든 구종 수집
10. 매 선수마다 다른 성장 과정

2. 초기 능력치 주사위
==================================================

초기 능력치는 플레이어가 직접 숫자를 배분하지 않는다.

"주사위 굴리기" 시스템을 사용한다.

초기 주요 능력치:

투수:
- 구속
- 제구
- 구위
- 스태미나
- 회복력
- 멘탈

타격:
- 컨택
- 파워
- 선구안
- 스피드

수비 능력치는 이후 확장 가능.

주사위를 굴린 결과에
선택한 투수 성향과 타자 성향 보너스를 적용한다.

예:

파이어볼러
- 구속 크게 증가
- 구위 증가
- 제구 약간 불리

정밀 제구형
- 제구 크게 증가
- 구속 보너스 적음

정통파
- 구속 / 제구 / 구위 / 스태미나가 균형적

변화구 마스터
- 구위 증가
- 변화구 성장 보너스

땅볼 유도형
- 제구 / 무브먼트 관련 보너스

컨택형
- 컨택 증가

파워형
- 파워 증가

스피드형
- 스피드 증가

시즌 시작 전에는 재굴림 가능.

==================================================
3. 능력치 범위
==================================================

기본 능력치는 원칙적으로 1~100.

단, 게임 내부 계산에서는 float 사용 가능.

화면에서는 정수로 표시.

능력치는 단순 성공 확률만 바꾸면 안 된다.

플레이어가 직접 차이를 느껴야 한다.

예:

제구 30
→ 클릭한 곳과 실제 공 위치 차이가 큼

제구 90
→ 거의 클릭 위치로 들어감

구위가 높음
→ 타자가 헛스윙하거나 약한 타구를 만들 가능성 증가

스피드 높음
→ 실제 베이스 러닝 속도 증가

스태미나 높음
→ 긴 이닝 동안 능력치 유지

5. 투구 조작
==================================================

스트라이크존 UI를 화면에 표시한다.

플레이어는:

1. 구종 선택
2. 마우스로 목표 지점 지정
3. 클릭
4. 투구

의 순서로 플레이한다.

매우 중요:

플레이어가 클릭한 지점은
"구종의 최종 목표 지점"이다.

예:

플레이어가 슬라이더로 바깥쪽 낮은 코스를 클릭했다면
슬라이더가 그곳에서 더 휘어서 다른 곳에 도착하는 것이 아니다.

슬라이더는

다른 위치에서 접근
→ 횡으로 휘어짐
→ 클릭한 목표점에 도착

해야 한다.

그 후 제구 능력에 따른 오차를 적용하여
최종 실제 도착점을 결정한다.

==================================================
6. 제구 시스템
==================================================

TargetPosition = 플레이어가 지정한 위치

ActualPosition = 실제 공이 도착하는 위치

제구가 높을수록:

ActualPosition ≈ TargetPosition

제구가 낮을수록:

ActualPosition이 TargetPosition에서 랜덤하게 벗어난다.

단순 완전 랜덤 금지.

Gaussian Distribution 또는 유사한 정규분포 방식으로 구현한다.

제구가 낮아도 가끔 정확하게 들어올 수 있고,
제구가 높아도 가끔 실투가 발생할 수 있어야 한다.

피로도와 멘탈도 제구 오차에 영향을 준다.

8. 무브먼트 예상 장치
==================================================

매우 중요한 UI.

이것은 공 전체 궤도를 보여주는 장치가 아니다.

플레이어가 마우스로 목표점을 지정하면:

"이 구종이 최종 목표점에 들어오기 직전에
어느 방향에서 얼마나 휘어서 들어오는지"

보여준다.

목표점:
파란 원

그 이전 공 위치:
반투명 공 잔상 여러 개

시간적 표현:

공 잔상 1
→ 공 잔상 2
→ 공 잔상 3
→ 공 잔상 4
→ 목표점

또는 작은 반투명 공 하나가 반복적으로 이동.

예:

슬라이더
↘ → → ●

커브
↓
↓
↘ ●

중요:

예상 궤적은 투수 능력치에 따라 정확도가 달라질 수 있다.

구위 / 구종 숙련도가 높으면
예상 무브먼트를 더 정확하게 보여준다.

9. 공 물리
==================================================

공을 단순 Transform.Lerp로 이동시키지 않는다.

공에는 독립적인 BallPhysics 시스템을 만든다.

필요 요소:

- 위치
- 속도
- 수직 속도
- 중력
- 공기저항
- 바운드 계수
- 지면 마찰
- 회전
- 구종 Spin
- 타구 속도
- 발사각

투구와 타구에서 같은 Ball 객체를 활용하되
상태를 분리한다.

예:

BallState.Pitched
BallState.Batted
BallState.Rolling
BallState.ThrownByFielder
BallState.Dead

10. 공 높이 시각화
==================================================

탑뷰 또는 공 추적 UI에서는
공이 공중에 있는지 지면에 있는지 알아보기 쉽게 한다.

높이 0
→ 작은 공

높이 증가
→ 공이 점점 크게 표시

매우 높은 타구
→ 확실히 큰 공

공이 다시 지면에 가까워지면
→ 다시 작아짐

그림자도 추가한다.

높을수록:
- 그림자 작아짐 / 흐려짐

낮을수록:
- 그림자 진해짐

11. 타자 AI
==================================================

상대 타자는 능력치 기반 AI다.

능력:

- 컨택
- 파워
- 선구안
- 스피드
- 좌/우타
- 성향

타자는 다음 판단을 한다.

SwingDecision:

- 공의 예상 위치
- 스트라이크 여부
- 카운트
- 구종
- 구속
- 구위
- 선구안
- 투타 상성

등을 고려.

선구안이 높은 타자는
존 밖 공에 덜 속는다.

컨택이 높은 타자는
배트에 맞힐 확률 증가.

파워가 높은 타자는
타구 속도 / 홈런 확률 증가.

12. 투타 좌우 상성
==================================================

실제 야구처럼 platoon advantage 적용.

일반적인 경향:

우투 vs 좌타
→ 타자 유리

좌투 vs 우타
→ 타자 유리

우투 vs 우타
→ 투수 유리

좌투 vs 좌타
→ 투수 유리

단순 +20% 같은 과도한 보정 금지.

작은 보정으로 구현.

예:

Opposite handed:
ContactEvaluation + 소량

Same handed:
PitcherAdvantage + 소량

구종 종류에 따라 추가 변화 가능.

예:
좌투 슬라이더 vs 좌타
→ 더 까다롭게.

14. 주루
==================================================

각 주자는 별도 객체로 관리한다.

절대로 단순:

bases[0]
bases[1]
bases[2]

를 이동시키는 방식에 의존하지 않는다.

Runner 데이터:

RunnerID
Name
Speed
CurrentBase
TargetBase
Position
RunningState

CurrentBase:

0 = 홈
1 = 1루
2 = 2루
3 = 3루
4 = 홈 득점

예:

Runner A
CurrentBase = 1

Runner B
CurrentBase = 3

이면 정확히 1·3루 상황이다.

UI와 3D 주자 위치는
반드시 같은 Runner 데이터를 읽는다.

16. 수비 AI 핵심 철학
==================================================

수비수를 단순히

"공에서 가장 가까운 선수"

로만 움직이면 안 된다.

FieldingCoordinator를 만든다.

타구가 발생하는 순간:

1. 타구 위치/속도/높이 예측
2. 각 수비수 예상 도착 시간 계산
3. 타구 담당 선정
4. 나머지 수비수 역할 재배정
5. 포구
6. 송구 판단
7. 베이스 커버
8. 백업

을 한다.

18. FieldingCoordinator
==================================================

공이 맞으면 각 수비수의 공 도착 예상시간 계산.

EstimatedTime:

거리
/
수비수 이동속도

+

반응속도

+

포지션 적합도 보정

예:

SS = 0.82초
2B = 0.74초
3B = 1.20초

→ 2B가 타구 처리.

하지만 2B가 SS 구역까지 이동했다면
SS는 가만히 있으면 안 된다.

예:

2B → FIELD_BALL

SS → 2B가 비운 지역 BACKFILL
또는 2루 COVER

1B → COVER_1B

P → BACKUP_1B

3B → COVER_3B

C → COVER_HOME

20. 땅볼 플레이
==================================================

절대로

공 → 수비수 도착 → OUT

으로 끝내지 않는다.

순서:

타격
→ 타자주자 즉시 출발
→ 공 짧은 바운드
→ 지면 충돌
→ 공이 굴러감
→ 수비수 접근
→ 수비수 포구
→ 1루수 / 커버 선수가 1루 이동
→ 송구
→ 공이 1루까지 실제 이동
→ 포구
→ 주자 도착 시간 비교
→ SAFE / OUT

55. 개발 응답 방식
==================================================

나는 Unity 초심자다.

따라서 코드를 한 번에 수천 줄 작성하지 마라.

각 단계마다:

1. 이번에 만드는 기능
2. Unity에서 만들어야 하는 GameObject
3. Hierarchy 구조
4. Inspector 설정
5. 생성해야 하는 C# 파일
6. 전체 C# 코드
7. 어느 GameObject에 붙이는지
8. 실행 방법
9. 정상 작동 모습
10. 오류가 날 경우 확인할 것

순서로 설명한다.

내가 "됐어"라고 확인하면
다음 단계로 넘어간다.

기존 코드를 수정할 때는:

"어느 파일의 어느 부분을 바꿔야 하는지"

명확하게 알려준다.

가능하면 일부 코드 조각보다
수정된 파일 전체 코드를 제공한다.
