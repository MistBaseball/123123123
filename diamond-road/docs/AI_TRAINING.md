# 주자·수비 AI 강화학습 (AI 훈련장)

수비수 AI와 주자 AI를 서로 겨루게 하며(self-play) PPO로 학습시키는 기능이다.
게임 규칙과 물리는 기존 엔진을 그대로 쓰고, AI는 **판단만** 배운다.

## 구성

| 파일 | 역할 |
|---|---|
| `web/lib/ai/config.ts` | 설정 파일: 타구 분포, 시작 상황, 보상, PPO, 과거 상대 풀, 평가 주기 |
| `web/lib/ai/scenario.ts` | 에피소드 = 타구 1개(타격 → 플레이 종료). 랜덤 상황 생성, 보상 이벤트 기록, 지표 |
| `web/lib/ai/agent.ts` | 정책망(선택지마다 점수 → softmax)과 가치망. 학습 중엔 확률로 뽑고, 실전은 최고점 |
| `web/lib/ai/ppo.ts` | 판단 단위 궤적, GAE, clip PPO, 엔트로피 보너스 |
| `web/lib/ai/trainer.ts` | 수집(`collect`), 학습기(`Learner`: 최적화기·과거 버전 풀·체크포인트), 평가(`evaluate`) |
| `web/lib/ai/rules.ts` | 비교용 고정 규칙 AI: 항상 안전 진루 주자, 가까운 베이스 송구 수비 |
| `web/lib/ai/lab.worker.ts` | 브라우저 Web Worker (훈련장) |
| `web/components/game/AiLab.tsx` | 개발자 메뉴 → AI 훈련장: 10배속 화면 1개 + 수비수 승률·주자 승률·학습 횟수 |
| `web/scripts/train-ai.mjs` | 같은 코드로 Node에서 학습 (스레드 병렬, JSONL 로그, 체크포인트) |
| 엔진 `engine.ts` | `battedBall()`(설정 분포 타구), `runnerBrain`/`fielderBrain` 연결부, `throwObserver` |

## 엔진에서 바뀐 것과 이유

- `contact()`를 "타구 값 계산"과 `launchBall()`(플레이 시작)로 나눔 → 설정 분포로 만든 타구를
  `battedBall({kind, distance, angle, flightTime})`로 넣기 위해. 실제 경기 타구 계산과 난수 순서는 그대로(회귀 검사 그대로 통과).
- 판단 지점에 학습 AI 연결부: 주자 목표 베이스(`thinkRunners`), 공 가진 수비수의 송구 베이스(`chooseThrow`),
  추격 중 송구/뛰어가 태그(`chaseRunners`). 무엇이 합법인지(포스, 앞 주자 추월 금지 등)는 엔진이 정하고 AI는 그중에서만 고른다.
- 학습 주자는 상황이 바뀔 때(공을 잡음·던짐·받음, 베이스 도착)나 1초마다만 새로 판단(`brainEvery`).
- 학습 주자는 한 플레이에서 방향 전환 2번까지(`brainTurns`, 런다운 포함). 아래 "허점" 참고.

## 보상 (config.ts에서 조정)

- 수비: 아웃 +1.0, 같은 플레이 두 번째 아웃부터 +0.5 추가, 실점 −3.0, 진루 허용 −0.2/베이스, 송구 실책 −0.3, 판단 1번당 −0.01
- 주자: 1·2·3루 도달 +0.2/+0.35/+0.5, 득점 +1.0, 아웃 −1.2(진루 보상 합 1.05보다 크게), 판단 1번당 −0.01
- 처음 사양(실점 −1.0, 진루 +0.2/+0.25/+0.3, 아웃 −1.0)으로 3차 학습한 결과는 아래 "결과(3차)". 실점이 아웃과
  같은 크기라 수비가 실점을 주고 아웃을 잡는 쪽을 택해서 실점 −3.0으로, 주자는 먼 베이스 가치를 키워서 4차 학습.
- "스텝"은 판단 1번. 시간(초)마다 깎으면 플레이를 빨리 끝내는 쪽(멈추기)이 유리해져 의도와 반대가 된다.
- 보상은 그 사건이 일어난 시점 직전의 그 팀 판단에 준다(GAE γ=0.99, λ=0.95).

## 학습

- PPO(clip 0.2, 4 epoch, 미니배치 512), 정책·가치망 각각 은닉 24.
- 20번 업데이트마다 양쪽 정책을 풀(최대 20개)에 저장, 플레이의 30%는 한쪽이 과거 버전(그쪽은 학습 안 함).
- 시드 고정(`seed`), 체크포인트 100번마다.

```sh
cd web
node scripts/train-ai.mjs 1500 ai-runs/run1      # THREADS=코어 수, FROM=체크포인트로 이어서
CFG='{"ppo":{"lr":0.0005}}' node scripts/train-ai.mjs 500   # 설정 일부만 바꿔서
```

## 평가 지표 (train.jsonl의 eval 줄)

같은 상황 묶음(시드 424242)을 7가지 조합으로 플레이: 주자-수비 = L(학습)·H(기존 손 AI)·S(안전 진루)·N(가까운 베이스 송구).

- 주자: 아웃율, 추가 진루 시도율/성공률/아웃률, 플레이당 득점
- 수비: 올바른 베이스 송구율(아웃 가능할 때 가장 확실한 베이스), 송구 아웃 성공률, 플레이당 실점, 송구 실책
- 평균 보상(양쪽), 같은 상황에서 기존 AI 대비 보상 차이와 표준오차(`vsHand`)
- 허점 감시: 주자 멈춤 비율(1초 이상 여유가 있는데 멈추거나 돌아감), 아웃 가능한데 안 던진 비율, 방향 전환 수, 3번 이상 방향 전환한 플레이 비율, 플레이 시간
- 훈련장 승률: 같은 상황을 기존 AI끼리 했을 때와 비교해 학습 주자가 더 멀리 가면 주자 승, 학습 수비가 더 잘 막으면 수비 승

## 학습 중 발견한 허점

1. **1차(방향 전환 제한 없음)**: 주자가 목표 베이스를 계속 바꾸면 수비(기존·학습 둘 다)가 그 주자를 잡으려 계속
   송구 → 그 사이 다른 주자 진루. 기존 AI 대비 득점 0.17 → 0.31.
2. **2차(런다운이면 제한 없음)**: 일부러 런다운에 걸려 송구가 오갈 때마다 반대로 뛰어, 단타가 그라운드 홈런이 됨
   (플레이 7초 이상, 득점 0.17 → 0.66). 기존 수비 AI의 약점(던질 때 주자가 돌아설 수 있음을 고려 안 함)을 찌른 것.
3. 대응: 런다운 포함 방향 전환 2번 제한, 학습 수비에게 "주자가 다른 베이스로 돌아갈 수 있는 시간"·"그 베이스로 뛰는 중인지" 정보 추가.
- 주자 멈추기 전략: 없음(멈춤 비율 1% 미만). 수비가 일부러 안 던지기: 없음(0%).

## 결과 (3차: 처음 사양 보상, 14.4만 플레이, Node 2스레드 약 20분, 시드 1)

최종 정책을 새 상황 2000개(시드 777)에서 기존 손 AI와 같은 상황끼리 비교했다.

| | 학습 AI | 기존 AI |
|---|---|---|
| 주자 보상 차이(같은 상황, ± 표준오차) | +0.017 ± 0.008 | 0 |
| 주자: 플레이당 득점 (상대: 기존 수비) | 0.211 | 0.177 |
| 주자: 아웃율 | 39.7% | 38.9% |
| 주자: 추가 진루 시도 / 성공 / 아웃 | 3.7% / 93% / 6.6% | 3.8% / 95% / 1.8% |
| 수비 보상 차이 | +0.014 ± 0.007 | 0 |
| 수비: 올바른 베이스 송구율 | 78.0% | 72.3% |
| 수비: 플레이당 실점 (상대: 기존 주자) | 0.194 | 0.177 |
| 방향 전환 / 플레이 시간 | 0.003번 / 4.2초 | 0.21번 / 4.2초 |

- 둘 다 보상 기준으로는 조금(표준오차 2배 정도) 낫지만 차이가 작다.
- 수비는 아웃을 더 잡는 대신 실점을 조금 더 준다. 보상에서 아웃(+1)과 실점(−1)의 크기가 같아서,
  "실점 1점 주고 아웃 1개"를 손해로 보지 않기 때문(실제 야구에서 1점은 아웃 약 3개 가치). 실점 −2~−3을 권장.
- 주자는 더 공격적으로 한 베이스 더 간다(득점↑, 아웃 약간↑).
- 주자가 버티는 전략: 없음(멈춤 1.6%). 수비가 일부러 안 던지는 행동: 없음.
- 실제 경기 적용: 아직 안 함(수비는 실점이 늘어서, 주자는 득점이 늘어 밸런스가 바뀌어서). 결정 후 적용·밸런스 재조정.

| 0 | 89.5% | 10.5% | 0.255 | −0.64 | −0.14 |

(기존 AI끼리 득점 0.168/플레이.) 수비가 앞선 구간(200~1000)에는 학습끼리 득점이 기존보다 낮고, 주자가
1100번 이후 따라잡아 앞서면서 다시 올라갔다. 자기 대전이라 시소처럼 오간다. 1500번째의 주자 이득은 주로
"3루 주자 땅볼 때 바로 홈", "타자가 내야 땅볼에도 전력으로 2루까지 노림"(송구가 늘어 실책도 늘어남)이고,
방향 전환 0.10번(기존 0.24), 3번 이상 방향 전환 0%로 낚시 행동은 없음.

학습 단계별 같은 상황 비교 영상: `web/dev-ai-replay.html`(개발 서버 전용)로 체크포인트를 프레임 단위로 재생해 만든다.
