# Claude에 처음 보여 줄 파일

## 프로젝트를 한 번에 이해하기

나는 Unity 초보이고 **고교 투수가 되어 투구·타격·주루·수비를 직접 플레이하고 성장하는 3D 야구 커리어 게임**을 만들고 있다. 최종 목표는 Unity 게임이다. 전체 감각을 먼저 확인하려고 웹 점검판도 만들었다. 비용 때문에 Claude로 이어 개발하려 한다.

이 자료는 2026-09-29 기준이다. 전체 프로젝트를 새로 만들지 말고 전달된 소스를 이어 개발해 달라.

### 지금 있는 것

- **웹 점검판 v03**: 4구종 마우스 목표 투구, 제구 오차, 타자 AI, 직접 타격·번트, 주루·도루, 자동/수동 수비, 포구·송구·포스/태그, 플라이 아웃, 기본 경기 규칙, 3/9이닝, 카메라 5종, 훈련·휴식·스카우트·시즌 진로, 브라우저 선수 기록 저장.
- **최근 고친 것**: 반대 주루 방향, 이미 진루한 주자에 대한 잘못된 1루 아웃, 플라이 포구 판정, 구종별 움직임 범위 표시. 이 내용은 `web/scripts/check-game.mjs` 회귀 검사에 있다.
- **Unity 패키지**: 마우스 클릭 지점으로 130km/h 중력 궤적 투구, 리셋·중복 클릭 차단·예상 궤적·HUD, 자동 씬 생성 및 검사 메뉴. C# 8개와 설치 안내를 포함한다.
- **미완성**: Unity 쪽 타격·주루·수비·경기·육성, 완전한 공 물리·수비 역할 분담, 개별 주자 영속 데이터, 전체 고교 일정, 희귀 구종, 부상·교체, 프로 리그 장기 커리어 등.

웹 기능은 물리·규칙 일부가 단순화된 점검판이다. 원래 기획 전체가 구현되었다고 말하면 안 된다. Unity 전체 프로젝트는 제공되지 않았고, 실제 사용자 PC의 씬·컴파일·Play Mode는 확인되지 않았다.

### 실행과 코드

ZIP 압축을 푼 폴더에서 `web`로 들어가 Node.js 24로 실행한다.

```sh
npm ci
npm run dev
```

http://localhost:5173 에서 플레이한다. 별도 API 키나 AI 계정은 필요 없다. 검사 명령은 `npm test`, `npm run typecheck`, `npm run build`다.

- 규칙: `web/lib/game/engine.ts`
- 화면: `web/components/game/DiamondGame.tsx`, `web/app/globals.css`
- 3D 렌더: `web/lib/game/field.ts`
- 호환 렌더: `web/lib/game/software-field.ts`
- Unity: `unity/PitchingMouseMVP/`
- 정확한 현재 상태: `docs/PROJECT_STATE.md`
- 중요한 규칙과 작업 방식: `AGENTS.md`
- 앞으로 할 일: `docs/ROADMAP.md`

Unity와 웹은 좌표 원점·투구 방향이 다르다. 웹의 1루는 포수 시점 오른쪽(world −X)이다. 상세 좌표와 아웃 판정 불변식은 `docs/ARCHITECTURE.md`에 있다.

원본 웹 커밋은 `3edb3a97f2beb23e01c61fc8701264fd9d028db1`이다. 인수인계판은 일반 Vite 실행 환경과 코드 포맷만 바꿨다. 기존 사이트는 그대로다.

### 내가 원하는 진행 방식

한국어로 쉽고 짧게 설명한다. 사소한 변경마다 허락을 묻지 말고 수정과 검증까지 수행한다. **큰 기능 추가·삭제나 구조 전환만 먼저 물어본다.** 확인할 수 있는 모델·추론 수준 선택지가 있다면 작업에 맞는 추천을 짧게 알려 준다. 실제 설정을 변경했다고 꾸미지 않는다.

Unity 작업은 필요한 C# 전체 파일, GameObject 구성, Inspector 참조, 실행 및 확인 방법까지 제시한다. 코드가 있는 것과 실제 Editor 테스트가 끝난 것을 구분한다. 내 프로젝트 파일을 볼 수 없으면 그 사실을 말한다.

비용을 줄이려고 전체 과거 대화나 기획을 매번 읽지 않는다. 현재 상태와 수정할 기능의 코드만 먼저 읽는다. 작업이 끝나면 변경 파일·검사·남은 작업을 짧게 기록한다.

## Claude에 붙여 넣을 첫 지시문

```text
첨부한 Diamond Road 인수인계 자료를 기준으로 내 3D 야구 게임 개발을 이어 맡아 줘.
먼저 AGENTS.md와 docs/PROJECT_STATE.md를 읽고 현재 코드와 기획을 구분해 줘.
웹은 점검판이고 최종 목표는 Unity야. 새로 만들거나 큰 구조를 임의로 바꾸지 마.
최근 주루 방향, 잘못된 1루 아웃, 플라이 아웃, 구종별 움직임 표시 수정은 보존해.
파일과 실행 도구에 접근할 수 있으면 web에서 npm ci, npm test, npm run build로 기준 상태를 확인해.
실행할 수 없으면 실행했다고 말하지 말고 필요한 파일·명령만 정확히 알려 줘.
첫 답변은 현재 완성 범위, 검증 결과, 가장 가까운 다음 작업 후보를 짧게 정리해 줘.
이후 내가 지정하는 기능은 작은 수정마다 재확인하지 말고 구현과 검증까지 진행해.
큰 기능 추가·삭제가 필요할 때만 물어봐.
```

## 사용하는 Claude 환경에 따라

**Claude Code 등 로컬 폴더를 읽는 환경:** 압축을 푼 `diamond-road-claude` 폴더를 프로젝트로 열고 위 지시문을 보낸다. 루트 `CLAUDE.md`가 `AGENTS.md`를 참조한다.

**Claude 웹 채팅/프로젝트:** 우선 이 파일, `AGENTS.md`, `docs/PROJECT_STATE.md`를 첨부한다. 그다음 작업에 필요한 코드 파일을 추가한다. ZIP 하나만 올리면 모든 파일을 읽고 로컬 Unity를 조작할 수 있다고 가정하지 않는다. 상세 업로드 순서는 `docs/UPLOAD_GUIDE.md`에 있다.

기존 사이트와 localhost의 선수 저장 데이터는 자동 공유되지 않는다. 현재 패키지에는 사용자의 브라우저 저장 기록이나 Windows Unity 프로젝트 전체가 포함되어 있지 않다.

환경 참고: [Claude Code 프로젝트 메모리](https://code.claude.com/docs/en/memory), [Claude Projects 안내](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects).
